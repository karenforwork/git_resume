產業真實痛點 (The Problem)

台北市大量餐飲店家常因「難停車、冷氣不夠強、候位久、外送包材問題」等非餐點核心因素收到一星差評。這些外部噪訊稀釋了真實的料理品質，導致真正用心經營的好餐廳在演算法與搜尋結果中被誤殺。

工程端解方 (The Solution)

建立全流程資料管線：系統性抓取 12 行政區數萬筆餐廳文字評論，運用自定義規則庫與特徵工程，抽離與食物無關之負評因子，重構客觀之「食物真實評價模型」，並將清洗成果妥善存入 MySQL。

專案實作技術亮點 (Technical Implementation)

  • 文字清洗策略：運用 Python 正則表達式與語意斷詞，針對「停車、冷氣、排隊、外送員」等維度建立權重排除規則，計算食物相關評論純度。
  • 資料庫正規化設計：建立包含店家基本資料表、行政區索引表、原始評論表與過濾重算歷史表的關聯式架構，優化查詢效能。
  • Airflow 工作流容錯機制：透過 Airflow DAG 劃分各階段任務依賴性，加入 Task 回報與重試次數設定，提升排程韌性。
  • Docker 環境封裝：撰寫 Dockerfile 與 docker-compose.yml 將 Airflow Webserver, Scheduler 與 MySQL 容器化，達成快速啟動與跨機一致性。
  • Tableau 決策儀表板：連接 MySQL 產出台北市地理分布圖與情緒差異對比圖表，讓餐廳經理人一鍵洞察被誤判星等的料理品項。
